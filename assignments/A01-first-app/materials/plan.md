# A01：学生向けHTML教材の制作・検証記録

> 教員向けの制作・検証記録。HTML3ページと貼り付け用コードの初版を作成済み。指定環境での通し確認前のため、学生配布はまだ行わない。
> [アプリ仕様](../README.md)・[教材作成方針](../../../docs/teaching-materials-guide.md)に従う。

## 学生に伝える目標

「画面に『こんにちは、Android！』と表示するアプリを作ります。文字を変えて、もう一度動かせるようになりましょう。」

配布時は最初に、教員が実装・検証したアプリの完成画面を見せる。初版では実行画像と誤認しないよう「説明図」と明記した図を掲載している。Javaの文法やAndroidの仕組みをまとめて説明することから始めない。

## 4コマ・360分の構成

各時間は、操作・待ち時間・確認・修正・質問を含む目安。実際に手順を通して検証した後、各コマ90分の範囲で調整する。

## 手順09の文章例

以下は文章の粒度の見本。画面上の操作名やボタン位置は、指定Android Studioで確認してから画像とともに記載する。

**この手順でやること**

画面に出る言葉を、日本語に変えます。

**操作する場所**

strings.xmlを使います。表示する言葉が書いてあるファイルです。開き方を忘れた場合は、教材内の「05 使うファイルを開いてみよう」へ戻ります。

**やってみよう**

1. strings.xmlを開きます。
2. `Hello, Android!`を探します。
3. この言葉だけを`こんにちは、Android！`に書き換えます。前後の`<string ...>`と`</string>`は残します。
4. ファイルを保存します。
5. アプリをもう一度実行します。
6. 練習用のスマートフォンの画面を見ます。

変更前：

```xml
<string name="greeting_message">Hello, Android!</string>
```

変更後：

```xml
<string name="greeting_message">こんにちは、Android！</string>
```

これはstrings.xmlの中の1行です。ファイル全体をこの1行に置き換えないでください。実際の教材では、この行が入る`<resources>`内の位置も示します。

**こうなればOK**

画面に「こんにちは、Android！」と表示されます。変更前後の実行画像を並べます。

**うまくいかないとき**

| 見えていること | 最初に確かめること |
| --- | --- |
| まだ英語が出ている | 保存したか、変更後にもう一度実行したか、実行が完了したかを確認する。 |
| 文字の下に赤い線が出た | 変更前後の例を見て、前後の記号を消していないか確認する。直せない場合は、開いているファイルと赤い線を教員に見せる。 |
| 同じ名前のファイルが複数ある | 手順05の場所と比べる。見分けられない場合はファイル一覧を教員に見せる。 |

実教材では「保存」「実行」の操作方法にも案内を付ける。スクリーンショットの位置だけで説明せず、確認済みの画面ラベルを併記する。

5. HTML3ファイルと画像を作成し、学生の操作手順だけで完成・提出まで進めるか確認する。

### 初版の実装と確認範囲

- `materials/` をフォルダーごと配布し、`lesson.html` をブラウザーで開く。外部CSS・フォント・JavaScriptの依存はない。
- 4コマ・計360分の12手順を収録。1操作ずつの説明、コード全文、変更前後、結果確認、つまずいた場合の案内を用意した。
- チェック欄と振り返り欄はブラウザー内だけの入力。保存機能はなく、記録には印刷を使う旨を学生に明示した。
- `assets/code/` の4ファイルは手順06の貼り付け用テキスト。完成プロジェクトではない。手順09ではstrings.xmlの言葉だけを日本語へ変える。
- `android.app.Activity` と標準の `Theme.Material.Light.NoActionBar` を組み合わせる。AppCompat用Activityと標準テーマを混在させない。`values-night/themes.xml` が生成されていれば同じ内容で置換し、API 29以降の強制ダーク化も無効にする。
- 本文18px、キーボードのフォーカス表示、横スクロールできるコード欄、幅に応じた1列表示、印刷用CSSを用意した。印刷プレビューと実際の拡大操作は未確認。
- 静的検証：HTML内のローカル参照・アンカー81件、重複IDなし、12手順・各回90分、コード全文とダウンロード4ファイルの一致、全XML例の構文を確認した。英語・日本語・変更練習の3文字列でaapt2のcompile/linkを確認した。javacは成功し、`-source 17`とシステムモジュールパスに関する警告1件が出た。
- 公式の[プロジェクト作成手順](https://developer.android.com/studio/projects/create-project)と[エミュレーターの管理](https://developer.android.com/studio/run/managing-avds)を参照した。Panda 2の操作ラベル・初期値は、これだけで確認済みとはしない。

### 配布までに残る確認

1. Panda 2のEmpty Views Activityから手順を通し、テンプレート・SDK・JDK・Gradle・AGPのバージョンと初期依存関係を記録する。
2. 授業用エミュレーターの機種・API・操作方式を固定し、C01〜C06を実施する。API 35以降のシステムバー、暗い色の端末設定、文字の折り返しも確認する。
3. 実際のIDEとアプリの画像を取得する。説明図と区別し、必要な操作の箇所に説明付きで追加する。
4. ZIP提出物からプロジェクトを開き、ビルドできることを確認する。提出先・締切・ファイル名を確定してHTMLの手順12へ反映する。
5. Windows/macOSでファイル保存・実行・スクリーンショット・ZIP作成の手順と、教材の直接表示・拡大・印刷を確認する。
6. 初学者役が教材だけで操作し、難しい説明や足りない案内を直す。確認後に「教員確認用 初版」の表示を配布版へ変える。
