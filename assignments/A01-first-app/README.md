# A01：はじめてのアプリ — 要件・アプリ仕様案

> 状態：内容確認用の仕様案。アプリのコードと操作手順の教材は未作成。
> 対応授業：第1週・第1〜4回（90分×4コマ＝6時間）。
> 上位方針：[授業計画](../../docs/course-plan.md)。

学生向け教材はHTML形式で作成する。[教材作成方針](../../docs/teaching-materials-guide.md)と[A01教材の章立て](materials/plan.md)に従い、難しい言葉をできるだけ使わず、1つずつ操作と結果を確認する構成にする。

## 1. アプリの目的

画面にあいさつの文字を表示する、1画面のアプリを作成する。学生が「自分でプロジェクトを作り、文字を変更して、動いたことを確認する」体験を得るための導入課題とする。

機能の多さや見た目の工夫ではなく、**プロジェクト作成→実行→ファイルの編集→再実行**を一通りできることを重視する。色・余白・画像を工夫する課題はA02、ボタンのイベント処理は第3週以降で扱う。

## 2. 学習目標

1. 指定された設定でAndroidプロジェクトを新規作成できる。
2. 実行先のエミュレーターを選び、アプリを起動できる。
3. MainActivity.java、画面XML、strings.xmlを開き、それぞれの役割を短く説明できる。
4. XMLが参照する表示文字列を変更し、再実行して画面への反映を確認できる。
5. プロジェクトを閉じて開き直し、再び実行できる。

Javaの文法、変数、条件分岐の事前知識は求めない。MainActivity.javaは「画面を表示する処理があるファイル」として読み、初回は表示に必要な共通部分をひな形で扱う。

## 3. 機能要件

| ID | 要件 | 期待する動作 |
| --- | --- | --- |
| F01 | アプリを起動できる。 | ランチャーのアイコンから起動すると、あいさつ画面が表示される。起動直後に終了しない。 |
| F02 | あいさつを表示する。 | 画面中央に、指定された文字列を表示する。 |
| F03 | 編集した文字を再実行で反映できる。 | 学生がソースの文字列を変更してビルド・再実行すると、新しい文字列を表示する。アプリ内に編集機能は設けない。 |
| F04 | 繰り返し起動できる。 | アプリを終了して起動し直しても、最後にビルドした文字列を表示する。これはアプリに含めた文字列であり、データ保存機能ではない。 |

ユーザー操作は起動と画面の確認だけとする。ボタン、入力欄、画面遷移、計算、データ保存、通信、ログインはA01の対象に含めない。アプリ名や表示内容に学生の本名・学籍番号を入れることは必須にしない。

## 4. 画面仕様

### Stitchの画面デザイン

必須課題の完成状態に対応するデザインは、Google Stitchの「26CM_Android1」プロジェクト内の「はじめてのアプリ (完成状態)」で管理する。

- プロジェクトID：`3692358824817406400`
- 画面ID：`49a1dc8271eb4772a77097136b37afc6`
- [Stitchの参照情報・画像とコードの取得状況](design/stitch.md)

画像・生成HTML・デザイン資料を取得し、以下の画面仕様と照合した。表示文言は一致しているが、色、画像の縦横比、タップ時の演出などに差分がある。原本と差分の詳細は上記の参照情報に記載する。実装・評価には以下の画面仕様を使用し、Stitchの取得物はデザイン参考資料として扱う。

教員が画面を実装する際はStitch MCPを使用し、対象画面の最新デザイン情報・画像・コードを取得してJava・XMLへ反映する。取得時点と仕様との差分を記録し、指定エミュレーターで確認した画面を学生用教材の完成見本にする。学生の演習にはStitchやMCPの設定を要求しない。

### 画面の構成

| 項目 | 仕様 |
| --- | --- |
| アプリ表示名 | はじめてのアプリ |
| 画面数 | 1画面 |
| Activity | MainActivity |
| レイアウトファイル | activity_main.xml |
| ルートレイアウト | LinearLayout。縦方向に配置する。 |
| 画面部品 | TextViewを1つ配置する。 |
| 文字の配置 | システムバーを避けたコンテンツ領域の中央。文字は中央揃え。 |
| 大きさ | 文字は24sp。TextViewは横幅match_parent・高さwrap_content。 |
| 余白 | コンテンツ領域の内側に24dp。システムバーを避ける余白とは別に確保する。 |
| 色 | 背景は白（#FFFFFF）、文字は濃い灰色（#212121）。 |
| テーマ | ライトテーマ。アプリ独自のツールバーやタイトルバーは設けない。 |
| 対象表示 | 教員指定のスマートフォン用エミュレーター・縦向き。A01では横向き専用レイアウトを作らない。 |
| 文字の収まり | 固定高さや1行への制限は設けず、幅が足りない場合は折り返して全文を表示する。 |

配置イメージ（枠は説明用で、アプリには描画しない）：

```text
┌─────────────────────────┐
│     システムの表示領域    │
│                         │
│                         │
│   こんにちは、Android！  │
│                         │
│                         │
│     システムの操作領域    │
└─────────────────────────┘
```

### 表示文字と学習中の変更

| 状態 | 表示する文字列 | 目的 |
| --- | --- | --- |
| 共通の初期画面を作成した状態 | Hello, Android! | まず全員で同じ画面を起動する。 |
| 必須課題の完成状態 | こんにちは、Android！ | 編集した日本語が画面へ反映されることを確認する。 |
| 追加の練習 | 学生が考えた短いあいさつ | 同じ操作を自分で繰り返す。必須課題の完成確認後に実施する。 |

表示文言はstrings.xmlの`greeting_message`に定義し、TextViewの`android:text`から`@string/greeting_message`を参照する。学生には「画面XMLは文字を置く場所、strings.xmlは表示する言葉」と説明する。リソースの詳しい使い分けはA02で扱う。

## 5. 実装条件と担当範囲

| 項目 | 条件 |
| --- | --- |
| Android Studio | Panda 2 \| 2025.3.2 |
| プロジェクト名 | A01FirstApp |
| パッケージ名・applicationId | jp.ac.jec.a01firstapp（教材用の統一案） |
| 言語・画面 | Java・View SystemのXML。 |
| ライブラリ | 新規プロジェクト作成時の初期依存関係のみ。追加しない。 |
| 処理の配置 | 画面表示に必要な処理はMainActivityに置く。独自の処理クラスは作らない。 |
| 端末機能・権限 | カメラ・位置情報などの端末機能、実行時の権限要求は使用しない。 |
| 動作環境 | インストール後の起動・表示にネット接続を必要としない。初回のSDK・依存関係の取得は別途準備する。 |

学生は教員の手順に沿って新規プロジェクトを作成する。最初から完成プロジェクトを配布して開くだけの課題にはしない。

教員は、Java・XMLを選択できるテンプレートと、その初期画面を本仕様にそろえる手順を指定バージョンで検証する。LinearLayoutへの変更、ライトテーマ、システムバーへの重なり防止、文字サイズ・色・余白は共通手順または短いひな形を用意する。初回は学生自身にこれらの値を設計させず、画面XMLを編集する場所と表示文字列の対応に集中させる。

## 6. 4コマの進め方

| 回 | 学習・作業 | 終了時に確認すること |
| --- | --- | --- |
| 第1回・90分 | 完成画面を確認し、新規プロジェクトを作成する。初回の同期とビルド、実行先の選択を行う。 | 自分のプロジェクトを作成し、初期生成されたアプリを起動できる。 |
| 第2回・90分 | ファイルの役割を確認し、共通手順に沿ってLinearLayout・TextViewの初期画面を作る。 | 「Hello, Android!」が表示され、MainActivity.javaと画面XMLを開ける。 |

| 第4回・90分 | 編集・再実行を自分で繰り返し、プロジェクトの開き直し、完成確認、確認問題、提出を行う。 | 完成条件を満たし、3種類のファイルの役割を説明できる。 |

インストールとエミュレーターの準備は原則として授業前に済ませる。同期や起動のトラブル対応は演習時間内で行い、早く終わった学生は文字変更の追加練習を行う。

## 7. 完成条件と動作確認

アプリの動作と、学生ができるようになったことを分けて確認する。

| ID | 確認操作 | 合格条件 |
| --- | --- | --- |
| C01 | 指定エミュレーターでビルド・実行する。 | エラーで停止せず、1画面が表示される。 |
| C02 | 必須課題の画面を見る。 | 白い背景に「こんにちは、Android！」が中央に表示され、文字が欠けずシステムバーに重ならない。 |
| C03 | `greeting_message`を一時的に「おはよう、Android！」へ変更し、再実行する。 | 変更後の文字が表示される。確認後は必須課題の文字へ戻し、再実行する。 |
| C04 | エミュレーターでアプリを終了し、ランチャーから起動する。 | 最後にビルドした必須課題の文字が再び表示される。 |
| C05 | Android Studioでプロジェクトを閉じて開き直し、実行する。 | プロジェクトを開く場所がわかり、同じ完成画面を表示できる。 |
| C06 | ファイルの場所と役割を確認する。 | MainActivity.java、activity_main.xml、strings.xmlを開き、それぞれの役割と今回変更した場所を説明できる。 |

説明は短文・指差しでもよい。色や文字サイズの暗記、日本語の流暢さ、操作の速さはA01の合否条件にしない。完成画面のスクリーンショットだけでなく、C03の編集・再実行を実演してもらう。

提出物は、学生が作成したAndroidプロジェクト一式と、必須課題の完成画面のスクリーンショット1枚を基本案とする。プロジェクトにはソース・リソース・Manifest・Gradleのビルド設定とWrapperを含める。ビルド生成物、端末固有のSDKパスを持つlocal.propertiesは提出対象から除く。提出先とファイル名の規則は授業の共通ルールとして別途指定する。

## 8. 教材・コード作成前に検証する事項

- 指定Android Studioでのテンプレート名・選択項目と、Java／XMLで作成できること。
- SDK・JDK・Gradle・Android Gradle Plugin・初期依存関係の固定値、エミュレーターの機種とAPIレベル。
- 初期生成コードから本仕様の画面にそろえる手順、ライトテーマとシステムバーの余白。
- 提出対象のファイルだけでプロジェクトを開き、ビルドできること。

これらは教員側の環境検証で確定する。現時点では、指定環境でのビルド・実行確認を済ませたとは扱わない。

仕様確認と環境検証の後、このフォルダに操作手順の教材（lesson.html）、課題文（exercise.html）、動作確認票（checklist.html）、開始用コード、教員用の完成例を順次追加する。現在は仕様案と教材の章立てを整理しており、アプリコードと学生配布用HTMLは未作成。
