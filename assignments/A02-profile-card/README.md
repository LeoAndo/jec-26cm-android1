## 1. アプリの目的と学習目標

画像、名前、あいさつを表示する1画面のアプリを作る。同じアプリを3週間使い、画面を作ることから、ボタンの処理、入力の確認へ進む。

1. 第2週：TextView・ImageView・Buttonを配置し、LinearLayoutの縦横の並び、入れ子、余白、文字の大きさと色を変更できる。
2. 第3週：String・intの変数と文字列の連結を使い、ボタンを押すとTextViewの表示を変更できる。XMLのidとJavaのfindViewByIdを対応させられる。
3. 第4週：入力した名前を取り出し、boolean・if／elseで空欄を確認してカードへ反映できる。完成コードを見ずにリセットボタンを追加できる。
4. 表示を予想して実行し、結果と変更した場所を短文や指差しで説明できる。

開始時はA01で、指定Android Studioでの実行、MainActivity.java・activity_main.xml・strings.xmlの場所、文字列の変更と再実行を学んでいる。変数、クリック処理、条件分岐を習得済みとはしない。

学年は初期値1のintで扱い、アプリ内で入力・変更しない。第3週には学年を2へ変える必須の予想・実行練習を設け、確認後は1へ戻す。数値を表示する際は文と連結し、setTextへ数値だけを渡すコードにはしない。

第4週の「あいさつする」は、入力欄ではなくnameTextViewに反映済みの名前を読む。入力の確認とあいさつの表示変更が別の操作であることを学ぶ。

### 入力の取り扱い

- 名前は日本語・英字などの文字列として扱う。数字だけでも禁止しない。入力欄は1行とし、数値への変換は行わない。
- 必須の空白確認は、半角スペース（U+0020）、全角スペース（U+3000）、その混在を含む。全角スペースを半角にそろえてからtrimで前後を除く。途中の空白は削除せず、全角だった場合のみ半角になる。
- 全角スペースの置換は、getText・toString・trimの説明に続けて、教員が意味と入出力例を示す短い補助行として用意する。文字コードや正規表現の自力実装は求めない。
- 文字数の上限判定は必須にしない。長い名前は表示側で折り返し、スクロールして読めるようにする。Unicodeの空白全種類の判定は扱わない。
- 入力中の自動反映、キーボードの決定キーによる反映、自動でキーボードを閉じる処理は必須にしない。

trimだけでは全角スペースは除けないため、前処理を分ける。[Java String.trimの仕様](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/lang/String.html#trim())。setErrorの案内は入力欄のフォーカス時に表示されるため、エラー確認では入力欄へのフォーカスも確認する。[TextView.setErrorの仕様](https://developer.android.com/reference/android/widget/TextView#setError(java.lang.CharSequence))。

### 保存と再起動

SharedPreferences・Roomなどによる保存は実装しない。ホームへ移動して戻るだけで初期化されるとは説明しない。状態の自動復元とデータ保存も同じものとして扱わない。

初期値の確認には、実行中のアプリを強制停止した後、ランチャーから新しく起動する。入力欄の自動復元や画面回転の仕組みは教員側で確認し、回転前の値を復元する独自処理は学生の必須課題にしない。

## 7. 追加の練習と提出

必須課題の確認後に、あいさつの文を変える、学習済みの色・余白を調整する練習を選べる。ステップアップは、別のあいさつボタンを1つ追加する練習とする。保存や別画面を追加する課題にはしない。

次週へ進む前に共通の必須状態へ戻すか、必須状態のコピーを残す。追加練習の完成例を次週の「変更前」として使わない。

C05〜C11の操作と、第16回で自分が追加したリセット処理は授業中に確認する。「自分で変えた場所」「空欄のときに行う処理」「リセットで戻すもの」の振り返りも授業内で行い、追加の提出物にはしない。日本語の流暢さや作業の速さは評価条件にしない。
